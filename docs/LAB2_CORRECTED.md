# SmartBrew AI - Group 28 - Lab 2 correction

Date: 2026-10-20

SmartBrew AI is a personalized coffee-machine system for office customers and maintenance technicians. The full requirements cover profiles, saved recipes, context/mood recommendations, customization, supplies, payments, receipts, diagnostics, privacy and service-failure fallback. The group's custom feature is loyalty redemption. The executable prototype implements ten selected feature groups with persistent local state and a browser interface.

## What changed after feedback

The feedback gave a positive final grade. This revision fills the requirement template (Lecture 2, slide 47), places Customer/Technician on the left and Payment Processor on the right, makes Customize Beverage the customer's entry and the base of natural-language extension, and repairs the saved use-case descriptions. It also clarifies omissions found during source coverage review. The original archive is unchanged.

## User stories

| ID | Name | Story |
| --- | --- | --- |
| US-01 | Browse Menu and Nutrition | As a Customer, I want to browse categories, prices and nutrition so that I can select a suitable available beverage. |
| US-02 | User Authentication | As a Customer, I want to create an account and log in using credentials or my registered NFC card so that I can access my profile. |
| US-03 | Profile Management | As a Customer, I want to update preferences and save, name and modify custom recipes so that I can reorder my drinks conveniently. |

## Use-case correction

Customer -- Customize Beverage (solid association). Process Natural Language Order --<<extend>>--> Customize Beverage. Customize Beverage --<<include>>--> Check Ingredient Availability. Analyze Mood --<<extend>>--> Generate Recommendations when enabled/opted in. Redeem Loyalty --<<extend>>--> Process Payment. Technician has independent solid associations with Manage Inventory and View Error Logs; viewing logs is not a mandatory refill step. Extensions point toward their base use case.

## Assumptions

- Prototype money uses integer ore (100 ore = SEK 1); demo prices/nutrition/ingredient quantities are illustrative and are not production dietary specifications.
- Loyalty: earn one point per whole SEK actually paid; one point redeems SEK 0.10, bounded by balance and price. Demo Alex begins with 250 points and SEK 200 prepaid credit; new accounts begin with zero.
- Customer orders may be placed as guest; profile/recipe/history and prepaid/loyalty features require customer login. Guest receipts use an unguessable capability token.
- Mood opt-in and the proposed 2-second response target are design refinements; the original brief does not prescribe consent UI, a numerical latency target or point-conversion rules.
